## 2. 契约（Zig 实现必须逐项对齐）

1. **Header**：默认 `{"alg":"HS256"}`；设置 `typ` 时为 `{"alg":"HS256","typ":"..."}`（键序固定）。
2. **Payload**：紧凑 JSON；`exp` / `iat` / `nbf` 为 **Unix 秒**。
3. **签名**：`HMAC-SHA256(密钥 UTF-8 字节, "header.payload")` → **base64url 无填充**。
4. **密钥**：`算法:密钥`，取第一个冒号后的**第二段**；`HS256:a:b` 的密钥是 `a`（对齐 C# `Split(':')[1]`）。
5. **验签**：常量时间比较摘要；**签名段必须是规范形态**（补 `=`、插空白、换标准字母表一律拒绝）。
6. **时间**：`now > exp` → 过期；`now < nbf` → 未生效；等值仍有效（对齐 C# `Expire < now`）。
7. **算法**：只按固定 HS256 验签，不读 header 的 alg 决定算法（规避 `alg=none` 攻击）；
   `strict_header_alg = true` 时额外要求 header 声明的 alg 为 HS256。
8. **错误文案**：`JWT格式不正确` / `签名解码失败` / `签名验证失败` / `负载解码失败` / `负载解析失败` /
   `令牌已过期` / `令牌未生效` / `未设置密钥` —— 与 C#、Rust 端一致。

## 5. 已知边界

1. **仅 HS256**：三端算法交集；C# 还支持 HS384/HS512/RS*，但 Rust 端只支持 HS256，故 Zig 与之一致。
2. **密钥不含冒号**：三端都按 `Split(':')[1]` 取值，`HS256:a:b` 会用 `a`。
3. **payload 键序**：互验不依赖键序（各自原文签名）；需要绝对字节一致时用 `encodeVerbatim` / `genraw`。
4. **`now` 由调用方传入**（`encodeObject` / `validate` 均显式传 Unix 秒），核心库不做隐式时钟读取——
   便于测试与跨端复现；CLI 用 `std.Io.Clock.real` 取当前时间。

### 2026-11-18 · 会话存储接入（文件 / Redis）与 C# 键空间镜像

**用户原话**：「这个能接入Redis或者其他用于存储JWT的方案么？不要每次重启都会丢失而导致要重新登录」

### 2026-11-18（二）· 「JWT 默认就是不能丢」固化为硬口径

**用户原话**：「jwt默认就是不能让丢吧」

**落实为三条默认行为**（新增 `Keeper.authorize` 统一放行判断，调用方不必自己 switch）：

| 情形 | 行为 | 依据 |

### 2026-11-18（六）· 多库建表能力对照（Pek.RCode 的 sync_schema_for ↔ Pek.ZCode）

**用户原话**：「还有多库按连接的 `sync_schema_for` 这个Pek.ZCode有实现么？」

**结论：能力有，接口形态不同。**

| 能力 | `Pek.RCode`（Rust） | `Pek.ZCode`（Zig） |
|---|---|---|
| 全量建表（所有连接） | `sync_schema()` | `syncSchema(s_main)` |
| **只建某连接的表** | **有**：`sync_schema_for(conn, include_model_level, include_network)`、`sync_schema_named(conn)`（`dal.rs:1286/1302/1316`） | **无对应入口** |
| 多库路由本身 | 有（按表级 `ConnName`） | **有且自动**：`model.tableConn(t)` 表级优先、模型级兜底；跨库表由 `syncSchema` 内部 `sessionForConn(conn)` 自动开连接执行（`dal.zig:1474` 起） |
| 未挂载连接的处理 | 由 `include_*` 参数决定是否跳过 | **拒绝静默降级**：连接未挂载直接报错并提示 `attachConnection` |
| 现成谓词 | — | `model.tableBelongsToConn(meta, conn)`（可直接用来补过滤入口） |

**落地（`Pek.ZCode` 提交 `1a66abb`，已推送）**：

| 入口 | 语义（与 Rust `sync_schema_for*` 对齐） |
|---|---|
| `syncSchema(s)` | 全量表：表级 `ConnName` 优先、模型级兜底，跨库自动开会话执行（行为不变） |
| `syncSchemaFor(s, conn_name, include_model_level)` | `conn_name = null` → 不按连接过滤（等价 `syncSchema`）；否则只处理表级 `ConnName` 命中该连接的表 |
| `syncSchemaForAny(s, conn_names, include_model_level)` | 多连接别名：命中**任一**即归属（大小写不敏感）；空列表 = 不过滤 |
| `ConnFilter` | 过滤结构（`conn_names` + `include_model_level`），内部只经 `syncSchemaInner` 一份实现 |

**三条语义要点（踩过的坑，改动时别退回去）**：

1. **过滤先于连接路由**：不匹配的表直接计入 `report.tables_skipped` 并 `continue`，
   **不会**去连未挂载的其它连接。多库部署里「只管一个库」时不会因为别的库没挂而整体失败。
2. **`include_model_level` 与连接名无关**：没有表级 `ConnName` 的表归属模型级连接，
   只要 `include_model_level = true` 就**始终处理**（即使 `conn_name` 指向一个不存在的连接）。
3. **连接名比对大小写不敏感**（`std.ascii.eqlIgnoreCase`），且两侧都 trim；与模型/`Dal.connName()` 口径一致。

**新增测试** `Pek.ZCode/tests/integration_sync_for.zig`（真实 SQLite，2 个用例）：
表级 `ConnName` 覆盖落点（`Second` 库才有 `SyncFor_Second`）、大小写不敏感、幂等（二次跑 0 变更）、
别名链、空列表不过滤、`Ghost` 连接名只跳表不报错。

```zig
var guard = http_auth.Guard.init(io, .{ .secret = secret, .keeper = &keeper });
```

#### 行为（三条，全部有断言的用例）

1. 取 `Authorization: Bearer <token>`（scheme 大小写不敏感）——缺失 / 非 Bearer → **401**，reason 为中文固定文案

3. `Keeper.check`：`invalid` → **403**（已登出/过期/踢线）；`untracked` → **放行**（沿用「任何存储问题都不能把用户挡在外面」的硬口径）

通过后写链路状态，业务 handler **不必再解析一次 JWT**：

| 键 | 来源 |
|---|---|
| `auth.uid` | `sub` 声明（字符串或整数都支持） |
| `auth.client` | 会话记录里的客户端标识（需配 `keeper`） |
| `auth.pwd` | 口令指纹（需配 `keeper`） |

豁免前缀默认 `/health`、`/healthz`、`/login`、`/api/login`、`/favicon.ico`（**前缀**匹配），
命中时不写任何 `auth.*` 状态——避免豁免路径上的脏身份残留。

#### 用例（4 个，覆盖两侧）

| 用例 | 断言 |
|---|---|
| 豁免路径 | `anonymous`，且 `auth.uid` 为空 |
| 缺令牌 / 非 Bearer / 别家密钥签的令牌 / 过期令牌 | 全部 401，reason 逐条核对 |
| 正常令牌（`bearer` 小写 scheme） | `allow` + `auth.uid == "42"` |
| 配 keeper：登记后 `allow` 且写入 client/pwd；`revoke` 后同令牌 → 403；无存储 → `untracked` 放行 | 三种存储状态全覆盖 |

**踩到的坑（已避免）**：`Keeper.check` 返回的 `State.Active` 内存由 **keeper 的 allocator** 持有，
`deinit` 后即失效；直接塞进 `Ctx.state` 会变成悬垂指针（和 `model_guard` 里 conn_name 同一类问题）。
