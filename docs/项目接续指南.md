## 1. 项目是什么

Pek 生态权限组件的 **Zig** 实现。当前提供与 C#、Rust **完全互相解析互用**的 HS256 JWT：

| 模块 | 内容 |
|---|---|
| `src/jwt.zig` | `Builder`（对齐 C# `JwtBuilder`：Issuer/Subject/Audience/Expire/NotBefore/IssuedAt/Id/Algorithm/Typ）+ `Jwt`/`Options` 便捷层（对齐 Rust `Pek.RPermissions`）；`encodeObject` / `encodeJson` / `encodeVerbatim` / `validate` / `parseUnverified` |
| `src/claims.zig` | 标准 claims（`sub` / `name` / `from` / `clientType`），`Claims.admin/app` 与 `toMap/fromMap` |
| `src/secret.zig` | `算法:密钥` 解析（严格对齐 C# `Split(':')[1]`，算法大小写不敏感，空密钥拒绝） |
| `src/main.zig` | `zperm` CLI：`jwt gen/genraw/verify/inspect/selfcheck`（输出与 C#/Rust 对拍工具对称） |

**定位**：凡「令牌需要与 C# / Rust 生态互认」的 Zig 项目统一引入本库模块，勿逐仓复制实现。

## 4. 关键设计（改动前必读）

1. **互通口径**（以本地 C# 源码为准，勿凭印象）：
   - `DH.NCore\Web\JwtBuilder.cs:77`：`HS256 => d.SHA256(s.GetBytes())`；
   - `DH.NCore\Security\SecurityHelper.cs:93`：`SHA256(data, key)` 在 key 非 null 时 = `HMACSHA256.HashData(key, data)` → **就是标准 HMAC-SHA256**；
   - `DH.NCore\IO\IOHelper.cs:1150`：`ToUrlBase64` = 去填充 + `+`→`-`、`/`→`_`；
   - `JwtBuilder.cs:181` `TryDecode`：HS256 走字符串精确比较；时间检查 `now > exp` / `now < nbf`。
2. **与 C# 的有意差异（更安全，勿"对着改"）**：只按固定 HMAC-SHA256 验签、不读 header 算法；签名比较为常量时间。
3. **`now` 显式传入**：`encodeObject` / `validate` 均要求 Unix 秒，核心库不读时钟 —— 这样能逐字节复现 C#/Rust 的令牌（见 `src/jwt_test.zig` 两条字节级断言）。
4. **键序**：Zig 用 `std.json.ObjectMap`（StringArrayHashMap，插入序），与 C# Dictionary 插入序一致，因此**同输入同时间下令牌与 C# 逐字节相同**；Rust 端同样一致。互验本身不依赖键序。

## 5. 坑与红线（已踩过）

- **Zig 0.17 API**：`std.json.ObjectMap` 是 **unmanaged**（`.{}` 构造 + `put(allocator,k,v)`）；文件/标准输出走 `std.Io`（`main(init: std.process.Init)`、`std.Io.File.stdout().writer(io,&buf).interface`）；**`std.time.timestamp()` 已不存在**，时间取 `std.Io.Clock.real.now(io)`；`build.zig.zon` 必须有 `fingerprint`。
- **HMAC 覆盖原文是 `header.payload`**（点号必须在内）——曾漏掉点号导致全部验签失败。
- **PowerShell 传 JSON 参数会吞引号**：CLI 一律用 `@file` 传负载（与 C#/Rust 工具同约定）。
- 中文 `.ps1` 必须 **UTF-8 with BOM**（`tools/continuity` 与 `tools/*.ps1` 已按此处理；现有两个脚本为全 ASCII，无需 BOM）。
- 验证时间相关行为一律显式传 `now`，勿依赖真实系统时钟。

## 6. 版本与发布

- 版本在 `build.zig.zon`（当前 **0.1.0**）；库本体以源码模块形式被引用，无 crates 式发布流程。
- 远程仓库：`https://github.com/RemoteAll/Pek.ZPermissions.git`（默认分支 `main`）。

   但 Zig 侧未提供刷新令牌的签发/轮换 API；
3. 包管理发布（若后续有其它 Zig 项目需以 `build.zig.zon` 依赖形式引入）。
