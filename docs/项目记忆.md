### Zig 0.17 API 坑（本轮实测）
- `std.json.ObjectMap` 是 **unmanaged**：构造用 `.{}`，`put(allocator, key, value)`；`get/keys/iterator` 不需要 allocator。
- 文件/标准输出走 `std.Io`：`main(init: std.process.Init)` 可取 `init.gpa` / `init.io` / `init.minimal.args`；
  `std.Io.File.stdout().writer(io, &buf).interface` 才是 Writer；时间是 `std.Io.Clock.real.now(io)`（**`std.time.timestamp()` 已不存在**）。
- `std.process.Args.Iterator.initAllocator(init.minimal.args, gpa)`；`std.Io.Dir.cwd().readFileAlloc(io, path, gpa, .unlimited)`。
- `build.zig.zon` 必须有 `fingerprint`（`zig build` 会提示正确值）。

### 会话存储与 Redis（2026-11-18）
- 用户诉求：「能接入Redis或者其他用于存储JWT的方案么？不要每次重启都会丢失」→「Redis的库我要安排弄，要对齐C#和Rust的」。
- **事实**：JWT 无状态，不配 store 时重启本来就不掉线；会丢的是「会话登记/吊销」记录（C# 用 MemoryCache 时重启清空）。
- `src/session.zig`：`Store`（vtable，available/get/set/del + 可选 sadd/srem/smembers，全部带 `now`）+
  `MemoryStore` + `FileStore`（JSON 快照 + `.tmp` rename 原子替换，重启不丢）+ `Keeper`。
- `src/redis.zig`：最小 RESP2（短连接，每次操作 connect/close）；`src/redis_store.zig`：`RedisStore` + `CSharpMirror`。
- 契约：Rust 键 `{prefix}session:{sha256}` / `userver:{uid}` / `userver:{uid}:{client}` / `sessions:{uid}`；
  C# 键 `jwt:token:access:{token}`、`jwt:token:bind:{refresh}`、`jwt:user:tokens:{uid}`（**字符串 JSON 数组，不是 Redis SET**）；
  `JsonWebToken` 的 `AccessTokenUtcExpires`/`StartTime` 是**毫秒**；`ExistsToken` 只判键存在。
- 语义：`exp <= now` 失效（不是 JWT 的 `now > exp`）；剩余不足一半才滑动续期且不越 `abs`；存储不可用 → untracked 放行。
- 坑：`fetchPut` 命中已存在键时**保留旧键**（返回旧键但不替换），别 free `old.key`，要 free 新传入的键；
  `getOrPut` 命中时新键未被采用也要 free；`std.Thread.Mutex` 在 0.17 不存在 → 自写 `SpinLock`（`std.atomic.Mutex` + `Thread.yield`）；
  `std.fmt.fmtSliceHexLower` 不存在 → 手写 hex。
- 状态：测试 19 → **33**（全过）；三语言对拍仍 5/5。**本机无 Redis**，网络路径与真实 C# 反序列化**未对拍**。

# Pek.ZPermissions · 多库过滤建表与建表链路

### 跨仓：Pek.ZCode 按连接过滤建表（2026-11-18，Pek.ZCode 提交 1a66abb）

- 入口：`Dal.syncSchemaFor(s, conn_name: ?[]const u8, include_model_level)` /
  `Dal.syncSchemaForAny(s, conn_names: []const []const u8, include_model_level)`；
  内部统一走 `syncSchemaInner(s, filter: ?ConnFilter)`，原 `syncSchema` 转调 `null`。
- `conn_name = null` 与**空连接列表**都表示「不按连接过滤」= 全量。
- **过滤先于连接路由**：不匹配的表计入 `report.tables_skipped` 后 `continue`，
  不会去连未挂载的其它连接（多库部署里只管一个库时不会整体失败）。
- `include_model_level = true` 时，无表级 `ConnName` 的模型级表**始终处理**，与被查连接名无关。
- 连接名比对：两侧 `trim` + `std.ascii.eqlIgnoreCase`。
- 测试：`Pek.ZCode/tests/integration_sync_for.zig`（真实 SQLite，2 用例：过滤落点/大小写/幂等/别名链/空列表）。

### 本仓库：SqliteStore 的建表入口

- `src/sqlite_store.zig:71`：`dal.syncSchemaFor(&s, dal.connName(), true)`；
  连接名取 **Dal 实际生效值**（模型 `Option/ConnName = Permissions`），不硬编码。
- 本模型只有模型级表 → 必须 `include_model_level = true`。
- 默认值由方言渲染：`ExpireAt` 的 `DefaultValue="0"` → `DEFAULT 0`（测试断言 `PRAGMA table_info` 的 `dflt_value`）。

### 2026-11-18（提交 ce9281b）：热路径性能实测 + 消除与 zzig 的重复
